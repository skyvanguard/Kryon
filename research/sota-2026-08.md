## 1. Fuzzing

**Base (sin cambios):** AFL++ sigue siendo el estándar de facto (5.02c = latest, benchmark de referencia en FuzzBench/OSS-Fuzz 2025-2026). libFuzzer = el ligero. honggfuzz = único por features. Lo que TENEMOS cubre el core.

**Frontier 2024→2026: fuzzing asistido por LLM** (dos capas distintas):
1. **Generación de harness/drivers por LLM**: Fuzz4All, LLM4Fuzz, FuzzGPT, harness multi-agente para Java (arXiv 2603.08616, 2026), fuzzing de inputs no-textuales con LLM (USENIX Sec'25). Survey: [Towards Reliable LLM-Driven Fuzz Testing](https://arxiv.org/html/2503.00795v1).
2. **LLM como "cerebro" de búsqueda**: [AIxCC](https://arxiv.org/html/2509.07225v1) (IC 2025 — LLM que dirige la mutación), [Semantic-Aware Fuzzing](https://arxiv.org/html/2509.19533v1) (2025), Branch Flipper (coverage-grounded, LLM rompe bloqueos de cobertura).

**Protocolo/estado:** [LibAFLstar](https://www.cs.ru.nl/~erikpoll/papers/LibAFLstar.pdf) (2025) — fuzzing de protocolos state-aware sobre libAFL (framework Rust). [StorFuzz](https://kevin.borgolte.me/files/pdf/icse2026-storfuzz.pdf) (ICSE'26) — diversidad de datos para romper plateaus (investigación).

**Java:** Jazzer sigue mantenido (motor Java de OSS-Fuzz; [guía oficial](https://www.code-intelligence.com/blog/java-fuzzing-with-jazzer)).

**Veredictos:**
- **SALTARSE** los frameworks de fuzzing LLM "turnkey" (AIxCC etc.): **YO SOY esa capa** — ya genero harness desde fuente, leo crashes y itero. El patrón LLM-driven va directo al skill (ver §5).
- **ADOPTAR: Jazzer** (esfuerzo BAJO): un jar + JDK 21 (ya instalado). Cubre targets OSS Java, hoy hueco total.
- **VIGILAR: libAFL/LibAFLstar**: solo si aparece un target de protocolo estatal complejo (coste de integración alto, Rust).

## 2. Análisis binario + exploit-dev

- **Ghidra 12 sigue siendo la opción headless correcta** para nosotros (verificado). Tendencia 2025-2026: **RE asistido por LLM vía MCP** ([ida-pro-mcp](https://github.com/mrexodia/ida-pro-mcp), [Cisco Talos: LLM como sidekick de RE](https://blog.talosintelligence.com/using-llm-as-a-reverse-engineering-sidekick/), [LLMs para decompilación — ACM](https://dl.acm.org/doi/10.1145/3803633.3803666)). Para mí, el equivalente agente-nativo YA existe: Ghidra headless + ExportDecompile + lectura directa del C (sin GUI/MCP).
- **HALLAZGO CLAVE: [google/bindiff](https://github.com/google/bindiff) — Google abrió BinDiff** (copyright 2011-2026), con **packages prebuilt** y soporte para **Ghidra** como backend de desensamblado (también IDA/Binary Ninja). Cubre exactamente el gap que diferí (Diaphora): diff de binarios parcheado vs no-parcheado, portar symbols/comentarios. **ADOPTAR (esfuerzo MEDIO)**.
- **Exploit-dev — mitigaciones de hardware ya son objetivo activo**: [bypass de ARM MTE con CVE-2025-0072](https://github.blog/security/vulnerability-research/bypassing-mte-with-cve-2025-0072/) (GitHub, 2025), investigación de Apple MIE, shadow stack/CET en estudio. Lección: **ASAN ≠ MTE ≠ CET — cada capa tiene bypasses documentados**; reportar el contexto de mitigaciones del target es parte del hallazgo.
- Heap: baseline glibc (safe-linking, tcache) sin cambios disruptivos; literatura clásica (Quarkslab, pwnissa) sigue vigente.
- pwndbg/GEF: los nuestros son latest.

## 3. Caza de vulnerabilidades + disclosure

- **La caza de vulnerabilidades con LLM ya es industrial**: [DeepMind CodeMender](https://deepmind.google/blog/introducing-codemender-an-ai-agent-for-code-security/) (agente de seguridad de código), [zero-day hunting con Claude Code](https://checkmarx.com/zero-post/learning-about-llm-based-zero-day-hunting-with-claude-code) (Checkmarx), agente "Mythos" (claims + [medición independiente](https://medium.com/@jithprime/mythos-measured-752fa9ff2859)), [síntesis multi-agente de harnesses para vuln discovery](https://arxiv.org/html/2604.20801v1) (2026).
- **La VERIFICACIÓN de claims de IA es ya metodología de primera**: [Stingrai — verificar un 0-day de IA en 5 minutos](https://www.stingrai.io/blog/verify-ai-vulnerability-discovery-claims) (PoC mínimo + trazabilidad en fuente + reproducible en <1 min). Esto es exactamente el estándar de PoC que ya tengo — formalizarlo.
- **Proceso CVE**: crisis NVD 2025 sigue latente; reserva de ID para 0-days existe (FAQ del programa CVE); para OSS: huntr (GHSA) + CNA del vendor. Mi skill cubre KEV/EPSS/SSVC; falta la pieza de **reserva 0-day + huntr** para caza OSS real.
- **Nueva categoría de targets con bounty**: apps LLM/agentes — [OWASP Top 10 LLM 2025](https://genai.owasp.org/llm-top-10/) (LLM01: prompt injection sigue #1) y [OWASP Agentic Skills Top 10](https://owasp.org/www-project-agentic-skills-top-10/) (nuevo, 2025/26: abuso de skills/herramientas de agentes).

## 4. Trends ofensivos web / AD / cloud

- **Web**: request smuggling sigue vivo — [Netty CVE-2025-58056](https://github.com/keycloak/keycloak/issues/42292) (afecta Keycloak y otros), [smuggling en HTTP/3](https://ieeexplore.ieee.org/document/10945253/) (IEEE 2025 — el protocolo NO la elimina), defensa nueva: [HTTP Request Synchronization](https://arxiv.org/html/2510.09952v1). Mi stack (smuggler.py, skills cherry-pick) cubre el estado actual.
- **AD 2025-2026**: bypass de mitigaciones de **reflejo de autenticación** — [CVE-2025-33073 NTLM reflection](https://www.praetorian.com/blog/cve-2025-33073-ntlm-reflection-one-hop/) (Praetorian), [bypass de reflection para SYSTEM](https://synacktiv.com/node/1339) (Synacktiv), [investigación de identidad Semperis (2 vulns → Kerberos DoS / takeover)](https://www.semperis.com/blog/identity-crisis-novel-vulnerabilities-leading-to-kerberos-do). Los vectores clásicos (Kerberoasting/AS-REP/ADCS) ya los cubro con netexec/impacket/kerbrute; el delta = **reflejo/bypass de relay 2025**.
- **Cloud**: [hackingthe.cloud 2025 year-in-review](https://hackingthe.cloud/blog/2025_wrap-up/) (estado del arte ofensivo cloud) y **[intrusión cloud asistida por IA: admin en 8 minutos](https://www.sysdig.com/blog/ai-assisted-cloud-intrusion-achieves-admin-access-in-8-minutes)** (Sysdig) — confirma que la ofensiva cloud agente-nativa ya se demuestra. Mi cloud-pentest (pacu/cloud_enum/AzureHound) sigue vigente; el delta = el loop agente (que ya soy yo).
